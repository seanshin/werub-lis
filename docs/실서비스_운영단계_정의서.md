# 실서비스 운영단계 정의서

> **이 문서의 목적은 "운영단계에 무엇이 있는가"를 확정하고, 지금 하는 일과 선을 긋는 것이다.**
> 작성 시점(2026-07-29) LIS는 **개발단계 마무리 중**이며, 여기 정의된 운영단계 작업은
> **아직 착수 대상이 아니다.** 개발 중에 운영단계 항목을 앞당겨 실행하면 안 되는 이유는 §2에 있다.

---

## 0. 단계 구분

```
[개발단계]  ──▶  [개시 전환]  ──▶  [운영단계]
 지금 여기          단절점            이 문서의 §4~§9
```

| 단계 | 정의 | 정본 문서 |
|---|---|---|
| **개발단계** | 코드·문서·테스트 완성. 합성 데이터로만 검증. **실 환자 데이터 없음** | `CHANGELOG.md` · `docs/개시전_체크리스트.md` A~G |
| **개시 전환** | 되돌리기 어려운 1회성 플립 묶음(수 시간). 이 순간 이후 실 환자 데이터가 들어온다 | `docs/개시일_컷오버_런시트.md`(실행) · `docs/개시일_리허설_런북.md`(상세) |
| **운영단계** | 실 진료 데이터로 상시 가동. 일·주·월·연 주기 운영과 인시던트 대응 | **이 문서** |

**단계 판정 기준(오해 방지):** 지금이 어느 단계인지는 날짜가 아니라 **실 환자 데이터 유입 여부**로 판정한다.
현재는 파일럿 합성 데이터만 있으므로 개발단계다.

## 1. 개발단계 종료 기준 (DoD)

운영단계 진입 자격은 아래가 **전부 충족**될 때 생긴다. 하나라도 미충족이면 개시 전환을 시작하지 않는다.

| # | 기준 | 현재(2026-07-30 실측) |
|---|---|---|
| D-1 | 기능 백로그 0 (이월 포함) | ✅ v1.52.0에서 이월 5건 종결 |
| D-2 | CI 전 게이트 통과 — build·lint·type-check·compose env·nav 도달성·색 토큰·마이그레이션 커버리지·정리 분류 | ✅ `infra/scripts/ci.sh` |
| D-3 | 서버 E2E 게이트 통과(lis_test 클린 초기화) | ✅ **453/453**(v1.54.0) · 단위 531 |
| D-4 | 개시 차단 항목 해소 | 🔴 **2건 잔여** — ①위험치 채널(아래 ⚠) ②조직 결재 A-1/A-2/A-3 실결재 0/3 |
| D-5 | 조직 결정(§H blocking: H1·H2·H5) 확정 | ⬜ 대기 — 콘솔 ⑤축 결정 등록에 **행 없음**(=미결). **선행 입력: H2 질의 4건 회신**(HIS Q1·Q3 / PACS Q1·Q4) |
| D-6 | 검사실·법무 서명(마스터 실값·보존기간) | 🟡 `signoff_record` **0건** — 참고치·QC가 전부 dev seed 대표값 |

**D-4~D-6은 코드가 아니라 값·결재·회신이다.** 개발팀이 앞당겨 처리할 수 없고, 처리해서도 안 된다.
부서별 의뢰·회신 양식·검증 방법의 정본은 **`docs/개시_잔여항목_의뢰_검증서.md`**(잔여 12건)다.

> **참고 — HIS 통합키 ③(토큰 시크릿) 회전도 실서비스 항목이다(2026-07-30 결정).**
> 2026-07-29 LIS 귀책 노출로 ①②(인증 키)는 당일 회전을 마쳤고, 남은 ③는 **개시 전환의
> 자격증명 컷오버(§3 · 체크리스트 B2)에 흡수**한다. 지금 돌리지 않는다.
>
> 근거: ⓐ 현재는 **개발단계**이고 대상은 파일럿 dev 키다(보호 대상이 합성 데이터뿐).
> ⓑ ②로 **인증 키가 이미 새 값**이라, 노출된 옛 값 단독으로는 `x-integration-key` 검사를
> 통과하지 못해 엔드포인트에 도달조차 못 한다. ⓒ 개시 때 **dev 클라이언트를 폐기하고 운영
> 자격을 새로 발급**하므로 지금 회전하면 같은 일을 두 번 하는 것이고, 회전 창(401→수기 폴백)만
> 생긴다. → **운영 자격 발급 시 일괄 처리.**

> ⚠ **D-4 ①의 함정 — "설정됨"이 곧 완료가 아니다.**
> `CRITICAL_WEBHOOK_URL`은 값이 들어 있어 화면에 `설정됨`으로 보이지만 **파일럿 시드 sink**
> (`/_seed/critical-sink`)이며 그 경로는 코드에 존재하지 않는다 — 즉 지금 통보는 전부 실패한다.
> `CRITICAL_WEBHOOK_SECRET`은 미설정. 콘솔 readiness가 이 값을 `SEED` 상태로 구분해 표시하므로
> **판정은 화면(SEED/OK)으로 하고, "값이 있다"로 판단하지 말 것.**
>
> ⚠ **D-4 ②도 같은 함정.** `/admin/gates`의 A-1/A-2/A-3·PACS는 전부 `APPROVED`로 보이지만
> A-1은 기입자가 `U00`(데모 계정), 나머지 셋은 **기입자조차 비어 있다** — DEV 플레이스홀더다.

## 2. ⚠ 개발단계에서 운영단계 작업을 앞당기면 안 되는 이유

실제로 판단을 그르칠 뻔한 사례를 남긴다. **"감시가 빨간색이니 치우자"가 가장 흔한 함정이다.**

### 2-1. 파일럿 유물을 지금 치우면 안 된다

현재 연계 감시는 `healthy: false`다 — `dlqDepth 4`, `undeliveredCritical 1`.
둘 다 **알려진 파일럿 유물**이고, `infra/scripts/pilot-cleanup.sql`의 작성 근거에 이름으로 명시돼 있다.

> 2026-07-22 점검에서 확인된 파일럿 유물(seed 위험치 2·reflex DLQ 4·미적재 오더 1)이 감시 baseline을 오염시켰다.

→ **개시 전환 단계 6(체크리스트 D1)에서 실개시 직전 1회** 정리하도록 이미 배정돼 있다. 지금 치우는 것은 이중 작업이자, 비가역 스크립트를 규정된 시점 밖에서 돌리는 것이다.

### 2-2. DLQ 재큐는 "정리"가 아니라 "발신"이다

`POST reflex/requeue-dlq`는 DLQ→FAILED·retryCount 0으로 되돌린다. 그런데 현재 서버는
`configured: true`이고 `HIS_REFLEX_RETRY=on`이므로, **재시도 크론이 2주 지난 Reflex 오더를 실제로 HIS에 밀어넣는다.**

- Reflex 조직 게이트 **A-1/A-2/A-3 미결** 상태에서의 게이트 우회
- 임상 맥락이 소멸한 오더 발행(트리거 결과가 이미 정정·취소됐을 수 있음)

→ **개시 전까지 재큐 금지.** 정상 재큐 시나리오는 "HIS 계획 점검 복구 후 backfill"뿐이다(`docs/handoff/운영_DLQ다운타임_SOP.md` §4.2).

### 2-3. 미확인 위험치를 ack하면 안 된다

`CN-260724`(혈액배양 S. aureus)는 `dispatch_status: FAILED`다 — **위험치 채널이 실 채널이 아니기 때문**이다
(2026-07-30 실측: URL은 파일럿 시드 sink라 존재하지 않는 경로로 POST → 실패. 최초 작성 시점에는 URL이 빈 값이었고,
원인은 달라졌지만 "통보가 도달하지 않는다"는 결론은 같다).
ack하면 **열린 적 없는 폐루프를 닫힌 것으로 기록**하고, 동시에 개시 차단의 유일한 가시적 증거를 화면에서 지운다.

### 2-4. 원칙

> **개발단계에서 감시 지표가 빨간 것은 정상이다.** 감시는 파일럿 유물까지 정직하게 세도록 임계가 0으로 설정돼 있다.
> 지표를 초록으로 만드는 것이 목표가 아니라, **개시 전환 직후 초록에서 출발하는 것**이 목표다.

## 3. 개시 전환 (단절점)

상세 절차는 `docs/개시일_컷오버_런시트.md`가 정본이다. 여기서는 **운영단계 관점의 의미**만 적는다.

| 성격 | 항목 | 되돌리기 |
|---|---|---|
| 🔴 비가역 | 파일럿 데이터 정리(`pilot-cleanup.sql`) — ⚠**전량 DELETE 방식이라 실 데이터 유입 후 오실행 시 전량 소실**. 기능화 기획 `docs/개시전환센터_기획서.md` P3 | 백업 복원만 가능 |
| 🔴 비가역 | 실 환자 데이터 유입 시작 | 불가 |
| 🟡 플립 | `NEXT_PUBLIC_DEMO=""` + web 재빌드(데모 계정 패널 제거) | 재빌드로 복귀 |
| 🟡 플립 | 데모 계정(U00~U08) 폐기·실 계정 강제 비번변경 | 계정 재생성 |
| 🟡 값 주입 | `CRITICAL_WEBHOOK_URL` · `OPS_WEBHOOK_URL` · `LIS_BACKUP_OFFSITE` | 설정 변경 |
| 🟡 자격 | HIS/PACS dev 자격 → 운영 자격(A-3 결재 후) · **HIS 토큰 시크릿 ③ 회전 동시 처리**(`rotate-his-key.sh --token`) | 설정 변경 |

**전환 완료 판정:** 정리 직후 연계 감시가 `healthy: true`(전 지표 0)여야 한다.
0에서 출발하지 않으면 이후 모든 경보가 신호인지 잔재인지 구분되지 않는다.

## 4. 운영단계 — 자동으로 도는 것 (무인)

운영자가 아무것도 하지 않아도 도는 작업이다. **각 크론은 env 스위치로 꺼져 있을 수 있으니 개시 시 켜짐 확인이 필요하다.**

| 주기 | 작업 | 스위치 | 꺼져 있으면 |
|---|---|---|---|
| 5분 | HIS 오더 폴링(증분·워터마크) | `HIS_ORDER_POLL=on` | **접수 자체가 중단** |
| 5분 | 결과·Reflex 발신 실패분 재시도(임계 초과 시 DLQ) | `HIS_REFLEX_RETRY=on` | 실패분이 FAILED에 적체 |
| 10분 | Reflex PreOrder 승인상태 폴링 | `HIS_REFLEX_POLL=on` | 승인/반려 미반영 |
| 3분 | 위험치 통보 상향(0 담당의→1 수간호사→2 당직전문의) | 상시 | 폐루프 미완결 방치 |
| 5분 | 위험치 미전달 재발송 | 상시 | 통보 유실 |
| 10분 | 연계 감시 판정 + 임계 위반 시 외부 통보 | `OPS_MONITOR≠off` | **이상을 아무도 모름** |
| 10분 | 청구 sweep(PENDING 재전송 + SENT/REJECTED 폴링) | `BILLING_SWEEP≠off` | 청구 적체 |
| 매일 08:00 | 혈액제제 유효기간 임박 경고 | 상시 | 만료 폐기 증가 |
| 매일 04:00 | 보존기간 경과 데이터 정리 | `LIFECYCLE_PURGE=on` | 무한 적체(**법무 확정 전에는 의도적 off**) |

**⚠ `LIFECYCLE_PURGE`는 보존기간 최종값이 법무 확정될 때까지 켜지 않는다**(체크리스트 A4·C8). 켜는 순간부터 삭제는 비가역이다.

## 5. 운영단계 — 사람이 하는 것 (주기)

### 5-1. 일 단위

| 시점 | 항목 | 판정 기준 | 화면 |
|---|---|---|---|
| 근무 시작 | 연계 감시 | `healthy: true`. false면 breach 문구대로 조치 | `/admin/integration` |
| 근무 시작 | 미적재 오더 대기열 | **0건**. 있으면 코드매핑 보정 후 재적재 | 〃 |
| 근무 시작 | HL7 오더수신 실패 | **0건**. 있으면 보정 후 재적재(v1.52.0) | 〃 |
| 근무 중 30분 | DLQ | ≥1건이면 즉시 조치(SOP §2) | 〃 |
| 상시 | 위험치 통보 미확인 | **0건 무관용**. 상향 단계 확인 | 대시보드 |
| 마감 | 미검증 결과·보고 대기 | 잔여 이월 사유 기록 | 결과·보고 화면 |

### 5-2. 주 단위
- QC 판정 리뷰(Levey-Jennings 추세·Westgard 위반)
- 미청구(CAPTURED) 적체·반송(REJECTED) 워크리스트 소진
- 외부위탁(sendout) 미발송 노화 건 확인
- 백업 성공 로그 확인(오프사이트 복사 포함)

### 5-3. 월 단위
- 사용자·권한 정기 재검토(퇴직·직무변경 반영), 휴면 계정 정리
- 감사 로그 이상 접근 요약 확인(실패·민감·업무시간 외)
- 디스크·DB 용량 추세 확인
- MDRO/항생제 감수성 누적(antibiogram) 검토

### 5-4. 분기 단위
- **복구 리허설 1회** — 실제 복원 + RTO 실측 (`docs/백업복구_운영절차서.md`)
- 보안 검토(권한 매트릭스·수용위험 재검토 시점 도래분)
- 보존기간 정책 재확인

### 5-5. 연 단위 — 표준 코드셋 개정판 반입
손 편집이 아니라 **개정판 통째 반입**이다. 반입=항상 DRAFT → **차이 확인** → 활성화(이전 버전 RETIRED 보존=판정근거 소명).

| 코드셋 | 개정 주기 | 화면 |
|---|---|---|
| AST 브레이크포인트(CLSI/EUCAST) | 연 1회 | `/admin/catalogs` |
| 법정감염병(ORGANISM/MDRO) | 개정 시 | 〃 |
| 세포병리 분류(Bethesda) · CAP synoptic · ICD-O-3 | 개정 시 | 〃 |
| 심평원 EDI 수가코드 | 개정 시 | `/master` — **차이 확인(dry-run) 후 반입**, 이어서 **미청구 EDI 재동기화** |

**⚠ 활성 카탈로그는 판정 엔진이 직접 소비한다**(`interpretMic`·법정감염병 분류·synoptic 검증 등). 활성화는 임상 판정을 바꾸는 행위이므로 차이 확인을 건너뛰지 않는다.

## 6. 운영단계 — 인시던트 대응

### 6-1. 등급

| 등급 | 정의 | 예 | 1차 대응 |
|---|---|---|---|
| **S1 임상 위험** | 결과가 틀리거나, 위험치가 전달되지 않거나, 취소된 검사가 수행됨 | 위험치 통보 채널 다운, 오더 취소 미반영 | 즉시 수기 폴백(전화 통보) + 원인 격리 |
| **S2 업무 중단** | 접수·결과입력·보고 중 하나가 불가 | HIS 폴링 중단, LIS 다운 | 다운타임 절차(§6-2) |
| **S3 지연·적체** | 기능은 되나 쌓임 | DLQ 적체, 청구 반송 누적 | 근무 중 처리 |
| **S4 경미** | 표시 오류 등 임상 무영향 | 라벨 오탈자 | 다음 릴리즈 |

**판정 원칙: 애매하면 한 등급 올린다.** 검사 결과는 되돌릴 수 없는 임상 판단의 근거가 된다.

### 6-2. 다운타임
- **HIS 다운** → LIS 발신은 계속 시도되고 실패분은 큐에 남는다(유실 없음). 복구 후 재큐→재발신. 접수는 **다운타임 오더 화면**(수기, RCP)으로 계속하고, 복구 후 HIS 오더번호를 대사한다. **대사하지 않으면 청구·이력이 이원화된다.**
- **LIS 다운** → HIS `ServiceRequest`에 오더가 잔존, 복구 후 폴링으로 유입. 위험치는 전화 통보로 폐루프 유지.
- **양측 다운** → 전면 수기. 복구 후 재발신으로 정합.

상세: `docs/handoff/운영_DLQ다운타임_SOP.md`

### 6-3. 에스컬레이션
위험치는 시스템이 자동 상향한다(3분 주기, 0 담당의→1 수간호사→2 당직전문의). **간격은 `CRITICAL_ESCALATION_MINUTES`로 조정하되, 임상 합의 없이 늘리지 않는다.**

## 7. 운영단계 — 변경 관리

개시 이후의 배포는 개발단계와 규칙이 다르다.

| 항목 | 규칙 |
|---|---|
| 배포 게이트 | `deploy.sh --build`가 **E2E 게이트를 프리플라이트로 강제**(우회 `SKIP_E2E=1`은 긴급만) |
| 빌드 | **항상 `--no-cache`** — 캐시가 무변경 이미지를 배포한 사고가 있었다(v1.35.0) |
| 배포 후 확인 | ① 러닝 이미지 코드 버전 ② 마이그레이션 적용 로그·컬럼 실재 ③ 헬스. **헬스 OK만으로 성공 단정 금지** |
| 스키마 변경 | 마이그레이션 파일 필수(`prisma/migrations/<ts>_<name>/migration.sql`). e2e는 `db push`라 **마이그레이션 누락을 못 잡는다** |
| 신규 env | `ci.sh`의 compose env 게이트가 배선 누락을 차단(과거 잠복 블로커 2회 재발 유형) |
| 운영 중 설정 변경 | 재기동 없이 `/admin/settings`(DB>env>기본값, 허용목록 밖 키 차단, 값 마스킹·감사기록) |
| 롤백 | 블루그린 — `deploy-bluegreen.sh` |

**변경 금지(회귀 방지):** 임상 안전 불변식(ABO 독립 방벽·균명 정규화·이차소견 누출 차단·자가검증 차단·정정 권한 비대칭 등)은 리팩터링 대상이 아니다. 이유는 `docs/보안_점검_2026-07-21.md`와 CHANGELOG에 각각 근거가 남아 있다.

## 10. 이 문서 기준 "지금 하지 않는 것" 목록

개발단계 마무리 중에 **착수하지 않는다**. 착수 시점은 각각 표기했다.

| 항목 | 착수 시점 |
|---|---|
| 파일럿 데이터 정리(DLQ 4·위험치 1·미적재 오더 — **2026-07-30 실측 동일**) | 개시 전환 단계 6 |
| DLQ 재큐 | HIS 계획 점검 복구 시 또는 개시 후 |
| 미확인 위험치 ack | 개시 후 실 통보 건에 한해 |
| `CRITICAL_WEBHOOK_URL`(시드 sink→실 채널)·`_SECRET`·`OPS_WEBHOOK_URL`·`LIS_BACKUP_OFFSITE` 주입 | 값 확정 후(개시 전환) |
| `NEXT_PUBLIC_DEMO` 플립·데모 계정 폐기 | 개시일 |
| HIS/PACS 운영 자격 전환 · **HIS 토큰 시크릿 ③ 회전** | A-3 결재 후 |
| `LIFECYCLE_PURGE` 활성화 | 보존기간 법무 확정 후 |
| AWS 서울 구축(H6~H10) | H1·H2·H5 결정 후 |

> ⚠ **위험치 채널 주입 직후 반드시 E2E를 한 번 더 돌려 발신이 0인지 확인한다.**
> E2E 게이트는 운영 `.env`를 컨테이너에 그대로 넘기므로, 웹훅 키가 언셋되지 않으면
> **배포할 때마다 테스트가 실 온콜 채널로 합성 위험치를 보낸다**(v1.54.0에서 언셋+단언으로
> 구조적 차단, 그 이전 구조에서는 실제로 나갔을 것). 값을 넣는 그 시점이 유일한 발현 시점이라
> 코드가 아니라 **절차로** 확인한다. 근거 `CHANGELOG.md` v1.54.0.
