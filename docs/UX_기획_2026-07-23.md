# LIS UX 고도화 기획 — 세련된 일관성 + 용어 설명 시스템

작성: 2026-07-23 · 기준 버전: v1.4.13 (화면 24종 · 역할 10종 · E2E 356)
성격: **기획 문서** — 구현은 Phase 게이트에 따라 별도 배치로.

## 0. 전제와 원칙

현재 UI는 기능적으로 완결(P0~P2·Q·화면화 배치 완료)이나, "만든 순서대로 자란" 흔적이 있다 —
화면마다 밀도·헤더·표 스타일이 조금씩 다르고, 임상 용어(HH/LL·델타·NO_RANGE 등)가 **아는 사람
전제**로 노출된다. 이번 기획의 원칙:

1. **임상 안전 우선** — 세련됨이 안전 장치(위험치 강조·확인 스트립·마스킹 독트린)를 약화시키면 안 된다.
2. **개시 임박 = 저위험 우선** — 시각 리디자인보다 **용어·라벨·일관성**부터. 대규모 레이아웃 변경은 개시 후.
3. **정본 하나** — 색·상태·용어·컴포넌트는 각각 정본 1곳(@lis/shared 또는 components/ui)에서만 자란다.
4. **화면은 역할의 작업대** — 역할별 랜딩(v1.4.9)의 연장: 각 화면의 첫 시선은 "지금 처리할 것"에 닿아야 한다.

## 1. 핵심 기획 — 용어 설명 시스템 (Glossary)

> 요청의 중심. "이 화면의 이 말이 무슨 뜻인가"를 시스템 어디서나 같은 방식으로 답한다.

### 1-1. 정본 데이터 — `@lis/shared` `glossary.ts`

```ts
export interface GlossaryEntry {
  key: string;          // 'delta-check'
  term: string;         // '델타체크'
  en?: string;          // 'Delta check'
  short: string;        // 1문장(팝오버 본문) — 예: "같은 환자의 직전 결과 대비 급격한 변화 감지 — 검체 뒤바뀜·오입력 의심 신호"
  long?: string;        // 용어집 페이지용 상세(판정 기준·LIS 동작·근거 문서 링크)
  category: '판정' | '상태' | 'QC' | '수혈' | '병리' | '미생물' | '유전체' | '연계' | '청구';
  see?: string[];       // 관련 용어 key
}
```

- **shared에 두는 이유**: 웹 팝오버·도움말 페이지·(향후) 인쇄 보고서 각주가 같은 문장을 쓴다.
  단일 파일 병합 원칙(index.ts) 준수.
- **초기 수록(약 60항목)** — 실제 화면에 노출 중인 것부터:
  - 판정: HH/LL/H/L/N, 위험치(panic), 델타체크, 자동검증(AUTO)/2차검증(VERIFIED)/보류(PENDING),
    보류사유 전체(CRITICAL·DELTA·QC·NO_RANGE·POLICY·NONNUMERIC·INSTRUMENT·SENDOUT), 참고치, 재검(rerun)/정정(개정)/버전
  - QC: Westgard 규칙(1-3s·2-2s·R-4s·10x), Levey-Jennings, 로트 크로스오버, EQA
  - 수혈: ABO 독립방벽, 교차시험(전자/AHG), 항체선별/동정, 특수요구(조사·CMV−·LR·세척), look-back, MTP, 냉장30분 규칙
  - 병리: 그로싱, 포매/블록/슬라이드, 사인아웃, 개정(amend) vs 추가보고(addendum),
