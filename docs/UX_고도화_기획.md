## 1. 디자인 시스템 확립 (기반)

### 1-1. 타이포·간격 스케일 고정

762회의 임의 크기를 **5단계**로 수렴한다. Tailwind 유틸 대신 의미 기반 클래스를 `globals.css`에 정의:

| 단계 | 용도 | 값 |
|---|---|---|
| `.t-page` | 화면 제목 | 20px / 700 |
| `.t-section` | 섹션 제목 | 15px / 700 |
| `.t-body` | 본문·표 셀 | 14px / 400 |
| `.t-meta` | 보조 설명·라벨 | 12.5px / 400 · ink-2 |
| `.t-micro` | 배지·각주 | 11px / 600 · ink-3 |

간격도 4·8·12·16·24만 사용(현재 혼재). 섹션 카드 패딩은 20px 고정.

**검증**: 위 5개 외 임의 텍스트 크기 사용을 `grep`으로 0에 수렴시키고, CI에 `text-\[1[01]px\]` 금지 정규식 추가.

### 1-2. 공용 컴포넌트 확장 (`ui.tsx` → `components/ui/`)

화면마다 복제되던 것을 컴포넌트로 승격한다. **신규 화면은 이것만 조합**하도록:

- `<Section title hint>` — 섹션 카드(제목+설명+본문). 현재 24화면이 각자 `<section className="bg-surface border...">` 반복
- `<DataTable columns rows empty>` — 표 헤더·zebra·빈 상태·모바일 가로 스크롤 일체화
- `<Field label hint error>` — 라벨+입력+오류 3종 배치 통일(현재 손수 조합)
- `<StatBadge tone>` — 상태 배지(현재 문자열 클래스 인라인 조립)
- `<Toolbar>` — 화면 상단 액션 바(검색·필터·주요 버튼 배치 규칙)

**검증**: 화면 2개(오더·수혈)를 먼저 이관해 코드 라인 감소·시각 동일성 확인 후 나머지 확대.

### 1-3. 색 사용 규칙 — **임상 안전 직결** 🔴

실측: `bg-crit`/`text-crit` **118회**, `teal` 162회, `indigo` 48회.
문제는 횟수가 아니라 **crit(위험) 색이 임상 위험치와 UI 강조에 섞여 쓰인다**는 점이다.
현재 crit로 칠해진 것들: 위험치 HH/LL · 환자 병합 버튼 · 위탁 발송 지연 배지 ·
EQA 부적합 · 게이트 반려 · 삭제/폐기 버튼 …

> **위험 색이 흔해지면 진짜 위험치가 묻힌다.** 이것은 미학이 아니라 안전 문제다.

**규칙 (정본화)**

| 색 | 의미 | 허용 용도 | 금지 |
|---|---|---|---|
| `crit` | **환자에게 즉시 위험** | 위험치(HH/LL)·ABO 불일치·회수 대상 수혈자·미확인 위험치 통보 | 일반 삭제 버튼·업무 지연·반려·부적합 |
| `warn` | 주의·확인 필요 | 보류 사유·만료 임박·미확정 결과·지연·부적합·반려 | — |
| `good` | 정상·완료 | 정상 판정·승인·통과 | 단순 성공 토스트 남용 |
| `teal` | **주요 동작**(primary) | 화면당 1개의 주 액션·활성 내비 | 정보 배지 |
| `indigo` | 보조 강조 | 버전·정정 표시·부가 정보 배지 | 주 액션 |
| `ink-2/3` | 중립 정보 | 메타·설명 | 상태 표시 |

**되돌릴 수 없는 파괴적 동작**(삭제·폐기·병합)은 crit **채움**이 아니라 **crit 외곽선 + 중립 배경**으로
표현하고, 확인 다이얼로그에서만 crit를 채운다. 이렇게 하면 목록 화면에서 붉은 면적이 급감해
위험치가 시각적으로 튄다.

**검증**: 목록 화면 캡처에서 crit 면적이 위험치 관련 요소로만 남는지 육안 + `grep` 카운트 감소
(118 → 위험치·수혈 안전 경로만, 목표 40 이하).

### 1-4. 시각 언어 — elevation·radius·border

실측: `shadow-*`/`rounded-*` **411회**가 규칙 없이 혼재(`rounded-lg`·`rounded-2xl`·`rounded-full` 혼용).

- **radius 3단**: 4px(배지·칩) / 10px(입력·버튼) / 16px(섹션 카드). 그 외 금지
- **elevation 3단**: `flat`(표·리스트 — 그림자 없음, 1px line) / `raised`(섹션 카드 — 아주 옅은 그림자 1단)
  / `overlay`(팝오버·모달 — 뚜렷한 그림자 + 배경 블러 없음)
- **테두리 우선**: 임상 화면은 그림자를 많이 쓰면 지저분해진다. 구획은 `--color-line` 1px가 기본,
  그림자는 "떠 있는 것"에만.

### 1-5. 모션 — 지금 사실상 없음 🟡

실측: `transition`/`animate` 사용 **4회**. 상태 변화가 즉시 점프해 "덜 다듬어진" 인상을 준다.
반대로 임상 화면에서 과한 모션은 방해다. **최소·기능적 모션**만 규정한다:

| 대상 | 모션 | 시간 |
|---|---|---|
| 버튼·링크 hover/active | 배경·테두리 색 | 120ms ease-out |
| 팝오버·드롭다운 | opacity + 4px 상승 | 140ms ease-out |
| 토스트 | 슬라이드-인/아웃 | 180ms |
| 표 행 갱신(값 변경) | 배경 1회 플래시(warn 5% → 투명) | 600ms |
| 스켈레톤 | 은은한 shimmer | 1.2s loop |
| 모달 | opacity만(스케일 금지 — 위치 착시) | 140ms |

**전역 규칙**: `prefers-reduced-motion` 존중(전부 0ms로), 위험치·경고 요소는 **깜빡이지 않는다**
(발작 유발·경보 피로). 로딩 스피너 대신 스켈레톤 우선.

### 1-6. 숫자·값 표기 — 임상값의 세련됨

기반은 이미 좋다: `.mono`에 `font-variant-numeric: tabular-nums` 적용됨 ✅. 여기에 규칙을 더한다.

- **검사값**: 표에서 **소수점 정렬**(우측 정렬 + tabular-nums). 마스터에 소수 자리 수(`decimals`)를
  두고 표시 자릿수를 고정(현재는 입력값 문자열 그대로 — `4.0`이 `4`로 보이는 사례 발생 가능)
- **참고치**: `4.0 – 5.6` (en-dash·양쪽 공백). 하이픈·물결 혼용 금지
- **시각**: 목록은 `07-22 14:03`, 상세·보고서는 `2026-07-22 14:03`. 상대시각("3분 전")은
  알림·감시 지표에만
- **건수**: 1,234 (천 단위 구분). ID·코드는 구분자 없이 `mono`
- **범위 밖 값**: 색만이 아니라 **화살표 기호**(↑↑/↑/↓/↓↓)를 함께 — 색맹 사용자 대응

### 1-7. 밀도(density) 모드

검사실은 목록을 길게 본다. 사이드바 하단에 **보통/조밀** 토글(로컬 저장)을 두고, 조밀 모드에서
표 행 높이·패딩만 축소(글자 크기는 유지 — 가독성 훼손 금지).

## 2. 용어·키워드 설명 기능 (신규 — 요청 핵심)

### 2-1. 용어 사전 데이터 (정본 1곳)

`packages/shared/src/glossary.ts`에 **용어 정본**을 둔다(API·웹 공용, 화면 하드코딩 금지):

```ts
export interface GlossaryTerm {
  key: string;            // 'delta-check'
  term: string;           // '델타 체크'
  short: string;          // 한 줄 — 툴팁·팝오버용(40자 내외)
  detail?: string;        // 문단 — 용어집 페이지용
  why?: string;           // 왜 중요한가(임상 의미)
  synonyms?: string[];    // 'delta', '델타', 'Δ체크' — 검색용
  category: 'result'|'transfusion'|'micro'|'pathology'|'genomic'|'ops'|'quality';
  seeAlso?: string[];     // 연결 용어 key
}
```

**초기 수록 대상(약 80항목)** — 화면에 실제로 뜨는 것부터:

| 분류 | 예시 용어 |
|---|---|
| 결과 | 델타 체크 · 위험치(panic) · 자동검증(auto-verify) · 보류사유(NO_RANGE·POLICY·QC·DELTA·CRITICAL) · 참고치 · 재검(rerun) · 정정(correction) · 확정(verify) · 희석배수 |
| 품질 | Westgard 규칙(1-3s·2-2s…) · QC 로트 크로스오버 · mean/SD · EQA · TAT · p90 |
| 수혈 | ABO 독립검증 · 교차시험(적합/부적합/추가검사필요) · 항체선별 · 항원음성 · 특수수혈 요구(방사선조사·CMV음성·백혈구제거·세척) · look-back · MTP · 냉장 30분 규칙 |
| 미생물 | 그람 예비보고 · MDRO · AST(S/I/R) · MIC · 선택적 보고 · 법정감염병 신고 |
| 병리 | 그로싱 · 블록/슬라이드 · 2단계 사인아웃 · 개정(amend) vs 추가보고(addendum) · 동결절편 일치도 · Bethesda · TNM · ICD-O |
| 유전체 | ACMG 분류 · 2차 발견(SF) · VUS · 동의 철회 · tier |
| 운영 | 워터마크(폴링) · DLQ · 대기열(미적재 오더) · 다운타임 오더 · add-on · correlation id(문의번호) |

### 2-2. 표출 방식 3계층

1. **인라인 용어 칩** — `<Term k="delta-check" />`
   본문 속 용어에 점선 밑줄. 클릭/포커스 시 **팝오버**로 `short` + "자세히" 링크.
   네이티브 `title=` 39곳을 이걸로 교체한다(모바일 미표시·스크린리더 불균일 해소).
   접근성: `<button aria-describedby>` + Esc 닫기 + 포커스 트랩 없음(가벼운 팝오버).

2. **용어집 페이지** `/help/glossary`
   분류 탭 + 검색(동의어 매칭) + 앵커 딥링크(`/help/glossary#delta-check`).
   각 항목: 용어 / 한 줄 / 자세히 / **왜 중요한가** / 관련 용어 / 이 용어가 나오는 화면 링크.

3. **전역 검색 진입** — 상단 검색(⌘K)에서 용어도 검색 결과에 포함(아래 3-2와 통합).

### 2-3. 상태값 자동 설명 (라벨링 통합)

지금 화면에 `NO_RANGE`·`DLQ`·`STAGED` 같은 **원시 코드가 그대로 노출**되는 곳이 있다(verify 보류사유 등).
`shared`에 `STATUS_LABEL` 맵을 두고 `<StatusChip code>`가 **한글 라벨 + 용어 팝오버**를 함께 제공한다.
예: `NO_RANGE` → "참고치 없음" 칩, 팝오버에 "참고치가 없어 정상/위험 판정을 할 수 없어 자동확정을 막았습니다."

### 2-4. 단위(unit) 설명·검증 — **별도 축** ⭐

용어와 별개로 다뤄야 한다. 단위는 **오해하면 값을 오판**하고, 현재 구조적 취약점도 있다.

**실측 현황**
- 검사 마스터의 단위 14종 사용 중: `%` `10*3/uL` `10*6/uL` `U/L` `fL` `g/dL` `mIU/L`
  `mL/min/1.73m2` `mg/L` `mg/dL` `mmol/L` `ng/dL` `s` `uIU/mL` `ug/mL`
- **`reference_range`에 단위 컬럼이 없다**(0개) — 참고치는 단위 없는 숫자다
- 결과 화면·보고서는 `result.unit`(입력자·장비가 준 문자열)을 **그대로** 출력
- 즉 **"참고치의 단위"와 "결과의 단위"가 같다는 보장이 시스템에 없다**(P2 잔여 항목과 동일 뿌리)

**UX 조치 (3단)**

1. **단위 사전** — `shared/units.ts`에 UCUM 표기 ↔ 사람이 읽는 뜻 매핑:
   `10*3/uL` → "천 개/µL (10³/µL)", `mL/min/1.73m2` → "mL/분/1.73 m² (체표면적 보정)",
   `uIU/mL` → "µIU/mL (마이크로 국제단위)". 화면의 단위 텍스트에 `<Unit>` 칩을 씌워
   호버/포커스 시 뜻·흔한 혼동(`mg/dL` vs `mmol/L`)을 보여준다.
   특히 **`10*3/uL` 같은 UCUM 표기는 검사자도 즉시 못 읽는다** — 표시용 별칭을 함께 노출.

2. **단위 불일치 시각 경고** — 결과의 `unit`이 마스터 `unitUcum`과 다르면 값 옆에 ⚠ 칩:
   "마스터 단위(mg/dL)와 다름 — 입력 단위 확인". **차단이 아니라 표면화**(장비가 SI로 올리는 경우 실재).
   백엔드 판정 로직은 건드리지 않는다(P2 단위 검증 본체는 검사실 서명과 함께 별도 처리).

3. **참고치에 단위 표기** — 참고치 표시 문자열을 `4.0 – 5.6 %`처럼 **마스터 단위와 함께** 렌더하고,
   보고서·검증·결과입력에서 동일 포맷을 쓴다(현재 화면마다 다름). DB 스키마 변경 없이
   `testMaster.unitUcum`을 조인해 표시하는 것으로 시작 → 서명 후 참고치 단위 컬럼 도입 시 자연 승계.

### 2-5. 구성(composition) 설명 — 무엇으로 이루어졌는가 ⭐

사용자가 자주 막히는 두 번째 지점은 "이 값/이 목록이 **무엇으로 구성**돼 있는가"다.

| 대상 | 지금 | 조치 |
|---|---|---|
| **패널** | `E6512` 하나로 보이고 전개된 항목은 안 보임 | 패널 칩 클릭 → **구성 검사 목록 팝오버**(Na·K·Cl). 오더·마스터·결과입력 공통 |
| **계산검사** | eGFR·LDL·AG·보정칼슘이 결과에 섞여 있고 출처 불명 | `CALCULATED` 배지 + 팝오버에 **공식과 입력 검사**("LDL = 총콜 − HDL − TG/5", 사용된 값 3개 표시) |
| **지표(TAT·p90·재검률)** | 숫자만 | 팝오버에 **산출 정의**("접수→최초 보고, 취소 제외", "p90 = 90%가 이 시간 내") |
| **보고서 구성** | 어떤 결과가 실렸는지 규칙 불명 | 보고서 머리말에 **포함 규칙 한 줄**("확정(AUTO/VERIFIED) 최신 버전만 — 미확정은 별도 표기") |
| **워크리스트** | 무엇이 왜 여기 있는지 | 목록 제목 옆 "포함 조건" 팝오버("접수·진행 검체 중 미보고 항목") |
| **화면 구성** | 탭·섹션이 많음(병리 7탭) | 각 탭에 한 줄 설명(§3-1 골격의 화면 설명과 동일 규격) |

**공통 구현**: `<Explain kind="panel|derived|metric|scope" id="...">` 하나로 처리한다.
용어 팝오버(`<Term>`)와 **같은 팝오버 컴포넌트**를 쓰되 내용 소스만 다르다
(용어=정적 사전, 구성=서버 데이터 조인). 이렇게 하면 사용자에겐 "밑줄 있는 건 누르면 설명이 나온다"는
**단일 규칙**만 남는다.

### 2-6. 약어 자동 인식

`TAT`·`MDRO`·`AST`·`MIC`·`QC`·`EQA`·`DLQ` 같은 약어는 화면 곳곳에 흩어져 있다.
용어 사전에 `abbr: true` 항목을 두고, 렌더 시 `<abbr>` 시맨틱 + 점선 밑줄을 자동 적용한다
(수동 태깅 부담 제거 — 제목·라벨 텍스트에 한정해 오탐 방지).

### 2-7. 첫 사용 온보딩 (가벼운 것만)

역할별 첫 로그인 시 **3단계 코치마크**(내 작업 → 주 업무 화면 → 도움말 위치). 로컬 저장으로 1회만.
과한 투어는 넣지 않는다 — 임상 사용자는 튜토리얼을 건너뛴다.

## 3. 화면 경험 개선

### 3-1. 화면 골격 통일

모든 화면을 `제목 + 한 줄 설명 + 툴바 + 섹션들` 골격으로 통일(현재 화면마다 상이).
한 줄 설명은 "이 화면에서 무엇을 하는가"를 12자~40자로. 도움말 15항목의 body를 재활용한다.

### 3-2. 전역 검색(⌘K) 확장

현재 환자·검체 중심 진입만 있다. 커맨드 팔레트로 승격:
- 환자/검체/오더 번호 → 해당 화면
- **화면 이름**("수혈", "청구") → 이동
- **용어**("델타") → 용어집 앵커
- 최근 방문 5개

### 3-3. 위험 액션의 시각 언어 통일

지금 confirm 다이얼로그는 있으나 색·문구 톤이 제각각이다. 3단계로 규정:
- **정보성**(단순 확인): 중립 버튼
- **되돌릴 수 있음**(보류·취소): warn 톤 + 사유 입력
- **되돌릴 수 없음/환자 영향**(출고·서명·폐기·정리): crit 톤 + **대상 요약 표시**(누구/무엇) + 확인 문구

### 3-4. 로딩·빈 상태·오류 3종 세트

화면마다 다른 처리를 컴포넌트로 통일: 스켈레톤(표 3행) · `EmptyState`(원인+다음 행동) · `ErrorText`(+문의번호).

### 3-5. 인쇄물 품질

보고서·라벨은 실제 산출물이다. 인쇄 전용 스타일 재점검(여백·표 줄바꿈·페이지 브레이크),
보고서 머리말에 병원명·검사실명·연락처 슬롯(마스터에서 주입).

### 3-6. 마이크로카피 — 문장도 UX다

실측: 같은 종류의 동작에 `저장`(10) `등록`(3) `확인`(3) `제출`(1) `실행`(1)이 섞여 있다.
사용자는 버튼 문구로 결과를 예측하는데, 어휘가 흔들리면 매번 다시 읽어야 한다.

**동사 사전(정본)**

| 상황 | 문구 | 금지 |
|---|---|---|
| 신규 데이터 생성 | **등록** | 저장·추가·제출 혼용 |
| 기존 데이터 수정 저장 | **저장** | 수정·적용 |
| 조회 실행 | **조회** | 검색·실행·불러오기 |
| 임상 확정 행위 | **확정**(결과)·**서명**(보고서)·**출고**(수혈) | 확인 |
| 단순 승인 다이얼로그 | **확인** / **취소** | OK·예/아니오 |
| 파괴적 | **삭제**·**폐기**·**회수**(대상 명시) | 제거·정리 |

**문장 톤**: 존댓말·평서문. 오류는 **원인 + 다음 행동**을 한 문장에("참고치가 없어 자동확정하지
않았습니다. 마스터에서 참고치를 등록하세요."). 시스템 내부 용어(`P2002`, `DLQ`)를 사용자 문장에
그대로 쓰지 않는다 — 라벨 칩(§2-3)으로 감싼다.

**금지 표현**: "오류가 발생했습니다"(무엇이 왜 없음), "잘못된 값입니다"(무엇이 잘못인지 없음),
느낌표 남용, 사과 반복("죄송합니다만").

### 3-7. 데이터 시각화 규칙

현재 차트는 2개(QC Levey-Jennings, EQA)뿐이고 색·축 규칙이 문서화돼 있지 않다.
앞으로 추세·워크로드 차트가 늘어날 것이므로 미리 규칙을 못 박는다.

- **색은 의미 우선**: 관리한계 밴드(±1/2/3SD)는 회색조, 위반점만 warn/crit. 계열 색을
  장식으로 쓰지 않는다
- **축**: 0 기준선 명시, 축 라벨에 **단위 포함**(§2-4와 연결), 눈금은 4~6개
- **툴팁**: 값 + 단위 + 시각 + 판정. 마우스 없는 환경(태블릿) 대비 탭 지원
- **빈 데이터**: 빈 차트 대신 `EmptyState`("최근 30일 QC 결과 없음")
- **접근성**: 차트 옆에 항상 **표 토글**(스크린리더·인쇄 대응)
- 구현 시 `dataviz` 스킬의 팔레트·마크 규칙을 따른다(차트 코드 작성 전 로드)

## 5-2. 개시 전 최소 묶음 (원 계획)

개시가 임박했으므로 **"체감이 크고 회귀 위험이 0에 가까운 것"**만 고른다. 아래 4개는
신규 파일 또는 표시 계층 한정이라 임상 판정 경로를 건드리지 않는다.

1. **색 규칙 정리(§1-3)** — crit 남용만 걷어낸다. 위험치가 시각적으로 튀게 되는 **안전 개선**이자
   가장 즉각적인 "정돈됨". 변경은 클래스 문자열뿐
2. **구성 설명(§2-5)** — 서버 데이터 그대로 쓰므로 사전 작성 없이 즉시 효과
3. **단위 표기·별칭(§2-4 1·3)** — 참고치에 단위 동반 + UCUM 별칭. 불일치 ⚠(2번)은 그다음
4. **용어 사전 1차(§2-1, 40항목)** — 화면 노출 빈도 상위부터. 80항목은 개시 후 확장

모션(§1-5)·타이포 수렴(§1-1)·컴포넌트(§1-2)는 **효과는 크지만 전 화면을 만진다** — 개시 후 첫 배치로.

## 6. 검증 기준 (완료 정의)

- 용어: 화면에 노출되는 원시 코드 0건(전부 라벨+팝오버), 용어집 80항목, 동의어 검색 동작
- 단위: 화면의 모든 단위에 사람이 읽는 별칭 제공(UCUM 14종), 참고치가 단위와 함께 표시,
  마스터↔결과 단위 불일치 시 ⚠ 표시(차단 아님)
- 구성: 패널·계산검사·지표·워크리스트 4종에 "무엇으로 이루어졌는가" 팝오버 제공
- 시스템: 임의 텍스트 크기 0건, 신규 화면이 `ui/` 조합만으로 작성 가능
- 회귀: E2E 무회귀(현 356) + 스크린샷 대조 2화면
- 접근성: 주요 6화면 키보드 단독 조작 가능, 대비 AA 통과
- 색: crit 사용이 위험치·수혈 안전 경로로만 축소(118 → 40 이하), 파괴 버튼은 외곽선형
- 시각 언어: radius 3단·elevation 3단 외 사용 0, 모션은 규정 6종만·`prefers-reduced-motion` 동작
- 문구: 버튼 동사가 사전 6종 내로 수렴, 오류 문구에 "원인+다음 행동" 포함률 100%
- 숫자: 표 검사값 우측·소수 정렬, 참고치 en-dash 통일, 범위 밖 값에 기호 병기(색맹 대응)

## 7. 무엇을 하지 않을 것인가 (스코프 가드)

세련되게 만들려다 임상 시스템을 망치는 흔한 길을 미리 배제한다.

- **화면 재배치·기능 이동 금지** — 사용자는 손이 기억한다. 이번 작업은 *같은 자리에서 더 읽기 쉽게*가
  전부다. 정보 위치를 옮기려면 별도 합의 필요
- **애니메이션으로 상태를 표현하지 않는다** — 깜빡임·펄스로 위험을 알리지 않는다(경보 피로·발작 위험).
  색+기호+텍스트가 정본
- **아이콘만으로 의미 전달 금지** — 임상 용어는 아이콘으로 압축되지 않는다. 아이콘은 항상 텍스트 보조
- **정보 밀도를 낮추지 않는다** — 여백을 늘려 "고급스럽게" 만들면 한 화면에 보이던 워크리스트가
  줄어 스크롤이 늘고 업무가 느려진다. 밀도는 §1-7 토글로 사용자가 정한다
- **브랜드 색을 상태 색으로 쓰지 않는다** — teal이 "정상"으로 오인되면 안 된다
- **개시 직전 전면 리팩터 금지** — §5-1 밖 항목은 개시 후

## 8. 측정 — "세련됨"을 어떻게 확인하나

주관을 배제하기 위해 배포 전후로 아래를 비교한다(대부분 정적 계측이라 CI에서 가능).

| 지표 | 측정법 | 목표 |
|---|---|---|
| 시각 어휘 수렴 | 임의 텍스트 크기·radius·shadow 클래스 종류 수 | 각 3~5종 이하 |
| 위험 색 집중도 | `bg-crit` 출현 수 / 위험치 관련 비율 | 비율 80% 이상 |
| 설명 커버리지 | 화면 노출 원시 코드 수(라벨 미적용) | 0 |
| 문구 일관성 | 버튼 동사 종류 수 | 6 이하 |
| 조작 효율 | 주요 5업무 클릭 수·키보드 완주 가능 여부 | 클릭 수 비증가·완주 100% |
| 접근성 | axe 자동 검사 위반 수(주요 6화면) | critical 0 |
| 회귀 | E2E·단위 | 무회귀(현 356/437) |

> 사용자 설문은 파일럿 사용자 3~5명에게 **개시 후** 짧게(5문항) — 개시 전 부하를 늘리지 않는다.
