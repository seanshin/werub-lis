## Z. 배포 절차 — 이미지 스모크(2026-07-21 장애 후 필수)

> **왜 생겼나:** v1.4.0 배포에서 `lis-api`가 기동 즉시 `Cannot find module '@lis/shared'`로
> 죽어 약 8분 다운됐다. 워크스페이스 패키지(`@lis/shared`)가 **로컬·E2E에서는 node_modules
> 심링크로 원시 TS가 해소되어 통과**하고, 컨테이너 런타임 이미지에서만 깨졌다.
> 로컬 빌드도 서버 E2E 325건도 이 결함을 잡지 못한다 — 검증 계층이 구조적으로 놓치는 영역이다.
> 되돌릴 이전 이미지도 남아 있지 않아 앞으로 고치는 것 외에 선택지가 없었다.

배포 전 반드시 수행:

1. **이전 이미지 보존** — `latest`를 덮어쓰기 전에 롤백 지점을 만든다.
   ```
   docker tag lis-api:latest lis-api:prev
   docker tag lis-web:latest lis-web:prev
   ```
2. **빌드** — 스키마 변경 시 `--no-cache`.
   ```
   docker compose -p lis -f docker-compose.prod.yml build [--no-cache] api web
   ```
3. **이미지 스모크(★ 이 단계가 없어서 장애가 났다)** — 컨테이너를 띄워 **실제로 기동하는지**
   확인한다. 마이그레이션은 건너뛰고(`RUN_MIGRATIONS=off`) 모듈 해소·부팅만 본다.
   **DB는 반드시 `lis_test`를 가리킨다** — 운영 `lis`로 붙이면 스모크 컨테이너에서 크론이
   실제로 돌아 위험치 에스컬레이션 등 운영 상태를 건드린다(2026-07-21 실제로 겪음).
   ```
   # ⚠ .env를 `set -a; . .env`로 소싱하지 말 것 — 값에 공백이 있으면(HIS FHIR scope 등)
   #   셸이 뒷 토큰을 명령으로 실행하려다 죽는다(2026-07-23 배포 중단 실제 발생).
   DB_PASSWORD=$(sed -n 's/^DB_PASSWORD=//p' ~/lis/infra/docker/.env | tail -1)
   JWT_SECRET=$(sed -n 's/^JWT_SECRET=//p' ~/lis/infra/docker/.env | tail -1)
   docker run --rm --network lis_default -e RUN_MIGRATIONS=off \
     -e DATABASE_URL="postgresql://lis:${DB_PASSWORD}@lis-postgres:5432/lis_test?schema=public" \
     -e JWT_SECRET="${JWT_SECRET}" -e PORT=4100 \
     lis-api:latest sh -c "timeout 40 node dist/main 2>&1 | tail -20"
   ```
   `Nest application successfully started`가 나와야 통과. `MODULE_NOT_FOUND`·`Cannot find`는 중단 사유.
4. **전환** — `up -d api web` 후 `ps`로 healthy 확인.
5. **사후 확인** — 마이그레이션 적용(`_prisma_migrations`), `/api/v1/metrics` 신규 지표,
   신규 화면 HTTP 200, 신규 엔드포인트 무인증 401.

**롤백:** 기동 실패 시 `docker tag lis-api:prev lis-api:latest && docker compose -p lis
-f docker-compose.prod.yml up -d api`.
